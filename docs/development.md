# Development and operations

This guide covers advanced configuration for the Linux/WSL development workflow. For the initial setup, see the [project README](../README.md#quick-start).

## Docker Engine + Compose: integration development

Docker Desktop is optional. On Linux install Docker Engine and the Compose plugin using your distro's supported instructions. In WSL2, the engine can run inside the Linux distro. Verify both before starting:

```bash
docker info
docker compose version
./scripts/optiq compose up --build
```

The Compose wrapper creates local environment files if needed, uses an explicit root `.env`, and forwards all subsequent arguments to Compose. It does not need the native Python dependencies installed. Compose overrides native database, mail, and queue settings with container service addresses, so both paths can share the generated JWT/Fernet keys. Keep those keys when retaining database volumes.

Postgres and Redis are private to the Compose network. Only app/API/Mailpit ports are published, on localhost. Container names are generated by Compose. `COMPOSE_API_PORT`, `COMPOSE_FRONTEND_PORT`, and `COMPOSE_MAIL_PORT` change published ports. Stop native dev before using the same API port.

```bash
./scripts/optiq compose logs -f backend worker
./scripts/optiq compose down      # Stops services; keeps database volumes
# After changing frontend dependencies, refresh its anonymous dependency volumes:
./scripts/optiq compose up --build --renew-anon-volumes
# Isolate another checkout and avoid published-port conflicts:
COMPOSE_PROJECT_NAME=optiq-other COMPOSE_API_PORT=8100 COMPOSE_FRONTEND_PORT=3101 COMPOSE_MAIL_PORT=8125 ./scripts/optiq compose up --build
```

Use this Compose file for local integration development. It runs reload servers and includes a local mail catcher; it is not a production deployment configuration.

Ollama is optional. Native mode uses `http://localhost:11434`. Containers use `host.docker.internal` with a Linux host-gateway mapping. Your Ollama listener must be reachable from the container network; override `COMPOSE_OLLAMA_BASE_URL` if it runs elsewhere. The application does not download models or install Ollama automatically.

## Optional MLflow and Ragas

Core dependencies are in `backend/requirements.txt`; test/lint tools are in `requirements-dev.txt`. The heavier MLflow and Ragas packages are in `requirements-extras.txt`.

```bash
./scripts/optiq setup --extras
# From the repo root, start a local tracking server in another terminal:
backend/.venv/bin/mlflow server --host 127.0.0.1 --port 5000 --backend-store-uri sqlite:///.local/mlflow.db --serve-artifacts --artifacts-destination .local/mlflow-artifacts
```

Set `MLFLOW_TRACKING_URI=http://localhost:5000` in `.env` and `NEXT_PUBLIC_MLFLOW_URL=http://localhost:5000` in `frontend/.env.local`, then restart dev. An empty tracking URI disables logging without importing MLflow. Experiments save results in the application database and use deterministic reference checks or user review. The default path never calls paid judges or embedding evaluators. The extras still contain legacy Ragas dependencies; installing them does not enable Ragas evaluation.

For Compose tracking:

```bash
INSTALL_EXTRAS=true COMPOSE_MLFLOW_TRACKING_URI=http://mlflow:5000 NEXT_PUBLIC_MLFLOW_URL=http://localhost:5000 ./scripts/optiq compose --profile tracking up --build
```

The tracking profile starts MLflow; `INSTALL_EXTRAS=true` installs its client and Ragas in the backend/worker image. Tracking is best-effort, so temporary tracking-server failures do not block the app.

## Configuration and data

`.env.example` describes native development. **Run setup rather than copying it unchanged**: it contains placeholders for generated secrets and relative paths which setup resolves to absolute paths.

| Variable | Purpose |
|---|---|
| `DEBUG` | Enables local-only backends when true |
| `DATABASE_URL` | SQLite locally; Postgres when deployed |
| `JOB_BACKEND` / `REDIS_URL` | `thread` locally; `rq` and Redis for durable jobs |
| `MAIL_BACKEND` / `MAIL_DIRECTORY` | `file` locally; private verification email files |
| `SMTP_*` / `RESEND_API_KEY` | Required delivery configuration when using `MAIL_BACKEND=smtp` |
| `JWT_SECRET` / `FERNET_KEY` | Token signing and encryption of stored provider keys |
| `FRONTEND_URL` | CORS and verification-link origin |
| `MLFLOW_TRACKING_URI` | Empty disables tracking |
| `OLLAMA_BASE_URL` | Native Ollama endpoint |
| `GOOGLE_CLIENT_ID` | Optional Google sign-in audience |
| `NEXT_PUBLIC_API_URL` | Frontend API origin; configured in `frontend/.env.local` |
| `NEXT_PUBLIC_MLFLOW_URL` | Optional dashboard tracking link |

Settings load repo-root `.env` automatically; `OPTIQ_ENV_FILE` selects a specific file for scripts/tests. Process environment values take precedence. Frontend `NEXT_PUBLIC_*` settings are embedded at build time in production.

`DATABASE_URL` must be configured explicitly. Set `FRONTEND_URL` for browser access and email verification links. CORS permits only that origin plus the optional JSON array `CORS_ORIGINS` (for example, `["http://127.0.0.1:3000"]`); there are no implicit localhost allowances. Configure `REDIS_URL` when using RQ and `OLLAMA_BASE_URL` when using the default Ollama endpoint. The frontend requires `NEXT_PUBLIC_API_URL` in `frontend/.env.local` or its deployment environment; it does not fall back to localhost.

Native data, email files, and optional tracking artifacts live under ignored `.local/`. Secrets live in ignored `.env`. Back up `.env` together with the database: replacing `FERNET_KEY` makes stored provider keys unreadable. Never commit or publish local mail files, which contain verification tokens.

If you already have an old Docker-oriented `.env`, setup preserves it. To adopt native defaults, move it to a private backup outside the repo, then rerun setup. Existing Postgres data is not automatically migrated to SQLite.


## Troubleshooting

| Symptom | Resolution |
|---|---|
| Python version is below 3.11 | Install a supported interpreter or set `OPTIQ_PYTHON` to its executable. |
| venv reports missing ensurepip | Install the venv package matching the interpreter, or install `uv`. |
| A development port is occupied | Stop the existing process, or use `./scripts/optiq dev --api-port 8100 --web-port 3100`. |
| Signup email does not arrive | Native mode saves messages in `.local/mail/`; Compose uses Mailpit at port 8025. |
| Experiment remains queued with RQ | Verify Redis connectivity and start the worker. |
| Native experiment stops during development | Backend reload interrupts thread jobs; use Compose for durable queue testing. |
| Docker cannot connect to its daemon | Start Docker Engine and verify `docker info`; installing the CLI alone is insufficient. |
| Existing configuration still points to container hostnames | Setup preserves `.env`. Keep a private backup and regenerate native configuration if switching modes. |

Run `./scripts/optiq doctor` to inspect the selected runtime and database configuration. Keep WSL checkouts under the Linux filesystem rather than `/mnt/c` for development.
